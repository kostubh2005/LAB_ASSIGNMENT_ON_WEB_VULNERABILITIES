OS Command Injection — In-band Demonstration

A local teaching application showing a vulnerable command path and an allow-list validation mitigation.

Lab safety: this application intentionally contains a command-injection flaw. It binds to localhost only. Do not expose it to a network or deploy it publicly. Stop it when finished.

INTENTIONALLY VULNERABLE

1. Vulnerable implementation

The server concatenates the form input into a shell command. The shell interprets command separators.

MITIGATED

2. Allow-list validation

The server accepts only a single valid IPv4 or IPv6 address. Other input is rejected before a process starts.

$RESULT_BLOCK

Suggested controlled test

Use this harmless marker payload in either form. The exact separator depends on the operating system:

Windows: 127.0.0.1 & echo INJECTION_PROOF

Linux/macOS: 127.0.0.1; echo INJECTION_PROOF

Expected: the vulnerable version prints INJECTION_PROOF as a separate line; the mitigated version rejects the entire input and says no OS command was run.

For coursework and local demonstrations only. This is not a production network utility.
